## Operational Preconditions

`pnpm verify list` prints phase names and group aliases. `pnpm verify synth` performs local synthesis. AWS execution is opt-in and maintainer-run: use the smallest relevant group, then the same selector for cleanup, for example `pnpm verify deploy replacement-safety` and `pnpm verify destroy replacement-safety`. Use a full suite only for changes spanning shared boundaries or a deliberately selected release candidate.

`pnpm verify deploy` does not rebuild provider archives. Run `pnpm build:bootstrap` after provider source or build-recipe changes. The runner rejects a staged archive whose provider-input, toolchain, environment, archive, or binary identity disagrees with `build-provenance.json`, and rejects missing provenance. `SHIN_ALLOW_STALE_BOOTSTRAP=1` explicitly bypasses this check; such a run does not establish current-provider evidence. Synthesis and destroy skip the deploy-time freshness check, while direct CDK use outside the runner does not gain it.

The construct requires the selected prebuilt archive unless `providerLambda.localBuild` explicitly selects compilation. Local builds default to deployment isolation and reject `ProviderSharing.STACK`. Missing archives fail synthesis instead of causing an implicit build. A locally compiling scenario declares `providerArchitectures: []` so the runner does not check an unused prebuilt artifact. The [breaking-change runbook](./breaking-changes.md) retains the recovery guidance for deployments made with an incompatible old provider.

Cleanup must be verified independently with exact resource-scoped probes. A not-found response proves absence; authorization, network, and ambiguous service errors do not. Partial cleanup is recovery material, not a completed verification pass. Raw evidence and identifiers remain outside git.

## Known Limitations

- The latest full-suite AWS baseline remains `fd6de8f`; subsequent local checks or a targeted group do not constitute a new combined AWS certification. The recorded baseline exercises arm64. Both packaged architectures have local package coverage, but that does not establish a current x86_64 AWS run.
- Marker entries need a planning pass for exact output length, MD5, and source validation. Changed output within the comparison spool threshold reuses those prepared bytes for a retryable upload. Larger output is streamed again; unchanged objects stop after planning. The fixed 16 MiB comparison spool budget is divided by `transfer.maxConcurrency`, including marker-free comparison work.
- Destination comparison metadata is O(manifest keys). Current and previous stale-key collections each have a 4 MiB retention cap accounting for key bytes and string records. Cleanup normally deletes those retained keys after successful transfer; overflow discards the affected retained list and uses one page-streamed re-list for the authorized cleanup legs. The manifest itself remains proportional to planned object count.
- The invocation-global source cap covers ZIP planning and retained source blocks in non-overlapping phases. Runtime, SDK, manifest, marker, comparison-spool, and transfer allocations use memory outside that cap; it is not a whole-process RSS bound.
- Imported buckets, SSE-C, SSE-KMS, SSE-DSSE, and destination encryption that cannot be proven at synthesis remain unsupported. The supported destination comparison contract is SSE-S3.
- Deployments are not transactional across objects. Source and output integrity checks prevent a failing streamed object from committing its final body frame, and transfer failure prevents stale deletion and invalidation, but earlier successful object writes may remain. Arbitrary external writers are not coordinated with retained-key cleanup.
